## Connecting scattered learning

Reading articles, following courses, and exploring repositories can produce a fragmented record of learning. Momentum, published in the Himma repository, brings activities and reflections into one workspace and uses them to suggest skill themes and learning directions.

The product supports personal reflection. A record of reading or an AI-generated summary is not proof of competence, and the learner needs a way to review and correct what the system infers.

## Review before import

Browser-history imports and pasted URLs enter a staging queue. The import service normalizes URLs and checks for duplicates against saved activities, pending candidates, and the incoming batch. Candidates remain pending until the learner chooses what to include or reject.

Confirmation uses a Prisma database transaction to create activity records and update candidate states together. This keeps the review step connected to the records it produces.

<Decision title="Keep AI output structured and attributable">
  The Gemini pipeline validates responses with Zod and checks that cited activity
  identifiers belong to the supplied context. Invalid responses can trigger a
  retry. A local heuristic path handles missing API configuration and quota
  failures. This provides a fallback without treating every returned insight as
  equally authoritative or as a verified assessment.
</Decision>

## A full-stack learning workflow

The Next.js interface talks to an Express API written in TypeScript. Shared contracts define request shapes, while Prisma connects the services to PostgreSQL. The API saves insight runs and accepts learner feedback; corrections can update the learner's skills and target path.

The engineering focus is the journey from captured activity to a useful reflection: a reviewable import queue, bounded AI context, structured responses, and an opportunity to correct the result.

## Evidence and limits

The repository contains the import-confirmation transaction, insight schema validation, citation checks, fallback generation, and profile-correction handling. These are implementation details that can be inspected through the source link above.

Citation checks establish that an identifier belongs to the input set; they do not establish that a model's interpretation is accurate. Learning summaries remain suggestions for the learner to evaluate.
