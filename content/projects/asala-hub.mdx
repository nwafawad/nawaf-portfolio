## Learning through an outage

A lost connection should not mean lost work. Asala Hub brings course materials and assignment drafts into the browser so students can continue with cached content while offline. Educators use the same platform to author courses, manage assignments, and return grades.

## From local draft to shared record

The Next.js client uses Dexie to store courses, modules, submissions, and mutation logs in IndexedDB. A submission can remain local and pending while the connection is unavailable. The sync provider monitors connectivity, batches queued changes, and records which writes have been acknowledged by the server.

Failed requests use a backoff schedule rather than a continuous retry loop. Pending and failed states stay visible in the queue, giving students a way to distinguish saved local work from work that has reached the server.

<Decision title="Make reconciliation explicit">
  A reconnect can bring duplicate requests, stale edits, and older client payloads.
  The sync service checks transaction identifiers and schema versions before
  processing changes. Submission reconciliation can combine compatible text
  additions or reject conflicting edits; grade changes follow educator permission
  checks. These cases need different responses, rather than a blanket
  last-write-wins rule.
</Decision>

## Across the stack

This full-stack project connects a Next.js and TypeScript interface to a FastAPI service and PostgreSQL database. The engineering focus is the boundary between local state and shared records: typed mutation payloads, server acknowledgements, and recovery when a batch cannot complete. Student, educator, and administrator views give each role its own workflow.

## Evidence and limits

The repository's sync tests target repeated submission requests, compressed payloads, compatible text merges, conflicting edits, and grade permissions. The sync provider and service show how those cases connect to the student workflow.

Offline access depends on content already available on the device. Drafts and queued changes remain in that browser's storage, and conflicts can require attention before synchronization completes. Acknowledgement from the server remains distinct from saving a local draft.
